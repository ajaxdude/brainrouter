# Leg L4 in full — Swap supervisor + platform probe

Goal (R5, R6-prep): brainrouter owns engine processes and model lifecycle — the API-driven generalization of the owner's icon scripts, inheriting their debugged invariants. L4 lands the abstraction + llama.cpp-family adapters + the shim; strixite/hipfire land in L5.

## Residency view (the input side of every budget/eviction/spawn decision)

`Resident = {catalog_id, source: shim | native | container | external, endpoint, gguf_path?, started_at, last_stream_completed}` assembled continuously by one observer:
- **Shim residents**: llama-swap `/running` polled per-model state (extends today's `fetch_slots` poller past its `running[0]` single-model assumption). Canonical GGUF path + key resolved through the imported catalog.
- **Native residents**: the swap registry's own live children (pid + health).
- **Container residents**: server-mode identities (existing `serving_identity.rs` registry).
Budget cap = probe-reported platform budget (`gtt_budget` on strix-halo, VRAM+policy elsewhere). Budget usage counts each model id ONCE: observed resident ⇒ `max(vram_estimate, reserved_gib if pinned)`; unmatched pin ⇒ full `reserved_gib`; then headroom. **The scheduler's `ensure(X)`: Residency view FIRST — when X's canonical GGUF (or catalog id) is resident anywhere, X is Ready-at-that-endpoint, no native spawn, no budget gate on attaches; budget admission applies only to ensures that would spawn** (pins-over-budget ⇒ every spawning ensure = explicit no-fit; resident attaches unaffected). The per-model flock (keyed on canonical GGUF, HELD BY THE CHILD — inherited fd, close-on-exec cleared; a surviving child keeps holding it across daemon restarts, which is exactly what adoption relies on; daemon crash releases nothing of the child's) guards native-vs-native races only; llama-swap and strixite are not lock participants, so the Residency view is the cross-mechanism guard. Acceptance (4) asserts SINGLE residency: native ensure of a shim-loaded model attaches (no new process, no second `/v1/models` listing of the same file); the budget gauge reports source=shim|native|container|pin.

## Platform probe (`src/platform.rs`)

- Detection (Linux): PCI enumeration (lspci/sysfs), `rocminfo`/kfd arch where present, `MemTotal`/`MemAvailable`, GTT from kernel params (`ttm.pages_limit`, `amdgpu.gttsize`), engine install markers (toolbox runtime, hipfire roots, strixite build root). macOS (L8): sysctl/Metal stub now.
- **`id` = the catalog platform id when detected hardware matches a feed platform (`strix-halo` for gfx1151), else `generic-<arch>`.** Today's feed platforms are `strix-halo`, `r9700`, `gb10`, `intel-b70` — NO gfx1100-class id exists, so fedora1 permanently resolves `generic-gfx1100`: its dashboard shows the explicit "unknown platform" banner + all toolboxes (the visible fall-open, by design), and a brainrouter catalog overlay (gufo-overlay precedent) is the named path to add a gfx1100-class platform entry if the feed lacks one. The compatibility matrix is independent vocabulary (arch-based, not feed-id-based). Consumers: dashboard `CURRENT_PLATFORM_ID` (replaces the hardcoded literal), toolbox image default, cockpit config `active_platform` (stays operator-set; the probe offers a one-click "set as active").
- Engine compatibility matrix (data, not code): strixite = gfx1151 + GTT ≥ ~100 GiB; gufo = gfx1151; hipfire = ROCm gfx9/10/11 discrete; llama.cpp = universal. Drives Engines-tab offers + reasons-not + install recommendations.

## Model registry + launch specs (`src/swap/`)

- `swap_catalog.json` (state dir): `{id, engine, files, ctx, quant, family, tools, vram_estimate, launch_spec {resolved args, env, port policy, served_model_alias = catalog id}, last_stream_completed}`. Seeds: (1) **IMPORT of the live llama-swap `config.yaml`** — inverse of `llama_swap_register.rs`, EXPANDING the macro chain (`${ls}`, `${common}`) against llama-swap's own settings so every entry records fully-resolved args; groups recorded as catalog metadata (L7 slot-sharing input); idempotent merge, `--dry-run` stable; (2) toolbox/server-mode catalog; (3) CLI additions.
- Launch spec validation: adapter-owned arg schema; engine-validated flags only; ctx/max-seq math documented per engine; the native llama-server launch MUST pass the served-model-alias flag set to the catalog id (precedent: gufo `--served-model-name`).
- Lifecycle: `Stopped | Loading | Ready (stem-asserted) | Draining | Failed`. `ensure(model_id) -> Endpoint`: consult Residency view (attach if resident anywhere); Stopped → budget check → evict-to-fit (LRU) → spawn (flock; concurrent ensure(X) = exactly one spawn, all attach); Loading → queue (cap, per-request position); Ready → proxy. Crash → bounded restart (plugin-supervisor pattern). Queue: in-memory, lost on daemon restart (clients retry; adopted running loads per below), queued requests cancellable via the in-flight row.
- Boot invariants (binding): single-instance flock per canonical GGUF, **held by the child process** (inherited fd, close-on-exec cleared — lock lifetime = engine lifetime, survives daemon restarts, releases on child exit/crash); stem assertion — for SPAWNING adapters (health returns the stem SET for shared endpoints like the shim; assertion scope = spawn validation, not per-request probing); start-ownership with **adoption markers for native children**: state-dir file per model `{pid, gguf, start_time, spec_hash, scope_name?}`, written atomically before spawn, cleared on stop. **Cgroup escape (binding): native children spawn via a transient systemd user scope (`systemd-run --user --scope`), the podman-scope precedent — children of the daemon's own cgroup die with the unit under `KillMode=control-group`, so direct-attached spawn CANNOT support adoption; without systemd (dev boxes) the fallback is plain setsid, adoption is best-effort and the Engines tab says so.** Daemon boot scans markers: live pid + gguf match + spec_hash match ⇒ ADOPT (native resident, no kill, no respawn); live pid + gguf match + spec_hash MISMATCH (upgrade changed resolved args) ⇒ adopt + mark `spec_stale` (a serving engine is never killed by an upgrade; the Engines tab badge + `swap ensure` explicit action converge it); dead pid/stale marker ⇒ cleanup.
- LRU: key = catalog id; clock = last STREAM COMPLETION (monotonic, recorded on SniffStream drop into the registry); in-flight check matches the ADDITIVE catalog-id stamp on in-flight rows (stamped at route time; alias-window strings unchanged), never evict with active streams; drain-then-evict; over-budget → queue + ETA; explicit no-fit after candidates exhausted (pins included in the arithmetic). **Authorized keeper changes (this Map's keeper list updated in v6): `src/inflight.rs` gains an additive `catalog_id` row field, route-time registration for queued/loading rows (v1 registers at stream start — the loading row is the L4 addition, stream-start registration semantics unchanged for v1 flows), and the SniffStream drop hook writing the registry clock. Additive-only; existing rows/fields/consumer behavior byte-identical (v1 floors + L1-L3 suites enforce).**

## Engine adapters (`swap::EngineAdapter`)

`probe() / spawn(LaunchSpec) / stop(handle) / health(endpoint) -> stem set / vram_estimate(entry) / capabilities(entry)`.
- L4 adapters: `llama_swap_shim` (ensure = Residency-view pass-through; ZERO routing change; circuit breaker = existing `LLAMA_SWAP_KEY`), `llama_cpp` native (direct llama-server, toolbox wrapper precedent; L7's path, proven in parallel here), `fake` (scripted: load time, stem set, crashes, load progress — the acceptance substrate).
- Load progress per source: shim = llama-swap `/running` state (poller extended per model); native = llama-server offers no load-progress endpoint ⇒ indeterminate + elapsed, ETA from EWMA of measured past loads persisted in the registry; fake = scripted. Matching per-ENDPOINT.
- Request shaping: the local llama-server-family sanitization (system-message merge, developer→system, assistant content/tool_calls fix) moves from `try_llama_swap` into a SHARED router-side contract applied to ALL llama-server-family endpoints (shim + native). Golden-body test: same request, shim vs native, byte-identical sanitized body.

## Acceptance (Ray)

(1) Fake-adapter lifecycle: ensure spawns; stem assert fail→Failed; crash→bounded restart; **N concurrent ensure(X) → one spawn, all attach, child-held flock released on child exit**; queue cap + cancel via inflight; LRU evicts least-recent-STREAM-COMPLETED, in-flight never evicted (catalog-id stamp match); start-ownership: foreign stem on port untouched; own child cleaned. (2) Budget: shim-resident model's native ensure ATTACHES (single residency, no second process); sized pins counted once (max(estimate, reserved)), subtract at admission (fake over-budget → explicit no-fit); eviction sequence asserted; pins-over-budget ⇒ every ensure THAT WOULD SPAWN = explicit no-fit (resident attaches unaffected — Residency precedes budget). (3) Adoption: host tier (systemd-run scope, owner machine): restart daemon while native model serving ⇒ adopt, no kill, no respawn; spec_hash mismatch ⇒ adopt + spec_stale badge, explicit ensure converges; fixture tier: marker-scan unit tests (stale/dead/mismatch); setsid-fallback environment documented best-effort.
