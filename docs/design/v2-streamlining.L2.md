# Leg L2 in full — Plugins + bridge pilot + minimal credentials store

Components:

- **Plugin core** (`src/plugins/`): `plugin.toml` manifest (`id`, `name`, `version`, `binary`, `min_daemon_version`, RPC grants, config-schema path). Supervisor: spawn enabled plugins at boot; restart-with-exponential-backoff capped at 60 s; 5 consecutive crashes → terminal `failed` state (no supervision until explicit `enable`); an `initialize` auth failure closes the connection and logs — it is NOT counted as a crash; stop = SIGTERM with grace, then kill (tokio-Child PID rule). Logs captured per-plugin to the state dir; displayed HTML-escaped (plugin logs carry untrusted chat text). Per-plugin UDS server at `$XDG_RUNTIME_DIR/brainrouter/plugins/<id>.sock` (dir 0700, socket 0600; reuse the repo's existing UDS precedents: stale-socket unlink + `peer_cred()` checks in `src/server.rs`; macOS peer-cred mechanism is an L8 confirm). Plugin state dir `$XDG_STATE_HOME/brainrouter/plugins/<id>/` (0700; holds config, kv, token, persistence, logs).
- **RPC v1 surface** (JSON-RPC 2.0; additive-only evolution; body cap 1 MiB, `chat.completions` bodies subject to the existing proxy limit; per-plugin in-flight cap 4 + queue 16, excess → JSON-RPC limit error — bounds cloud-spend loops pre-L6). Connect handshake `initialize`: plugin id + token (daemon-minted at install, stored `plugins/<id>/token` 0600, passed to the spawned child via env `BRAINROUTER_PLUGIN_TOKEN`); daemon checks token (constant-time), peer uid, and `min_daemon_version` at connect, returns grants + protocol version. Methods (token + per-method grant gating): plugin→daemon `chat.completions` (full router path; routing events carry additive `source: plugin <id>` so the Sankey HARNESS bucket shows plugins), `models.list`, `routing.events.tail`, `inflight.list`, `config.get/set` + `kv.get/set` (namespaced, state dir), `secrets.get` (ONLY credentials granting this plugin), `notify`, `set_status`; daemon→plugin `config.changed`. Unknown method → −32601.
- **Minimal credentials store** (`src/credentials.rs`): `credentials.json` (0600, atomic owner-only writes); values masked in all APIs/logs/`config show`, Debug-safe; `resolve(credential_id) -> Result<SecretString>` single implementation, never panics — a resolve failure is fatal-at-boot for the consumer, reported via `set_status` before exit, letting the supervisor mark `failed` rather than loop. Kinds `store` (value), `env`, `file` (ops escapes). Grants live on the credential (credential → plugin ids); removing a plugin drops grants naming it, logged. Migration: v1 plaintext `bridge.discord.token` → store credential granted to `bridge` — snapshot first, `--dry-run` preview, logged. Signal has NO v1 YAML secret: signal-cli state lives in `bridge.signal.storage_path`, out of store scope in L2.
- **Bridge plugin** (`plugins/bridge/` workspace crate → binary `brainrouter-bridge`): `src/bridge/*` moves as-is (behavior unchanged). Signal keeps its DIRECT llama-swap listing via the live `llama_swap_url` config key (v1 parity; `models.list` stays available for future plugins, Signal's `!br list` payload must not change at L2). Config schema = v1 `bridge.*` keys MINUS `bridge.discord.token` (token reaches the plugin only via `secrets.get`). Persistence: on first plugin start, COPY the six v1 JSON files (`sessions`, `channel-models`, `work-dirs` per transport) into the plugin dir if absent; v1 originals left in place for revert; move recorded in the migration snapshot; restore = `brainrouter migration restore v2.0-p2`.
- **CLI**: `brainrouter plugin install <dir>|list|enable|disable|remove|status|config set <id> [k=v]` (install copies to the state dir, mints the token, registers grants; reinstall preserves token + state; remove cleans state, drops grants naming the plugin). Per-transport pause: the v1 `bridge.{discord,signal}.enabled` keys move into plugin config, edited via `plugin config set` / the Plugins tab.
- **Core removals**: cargo features `bridge-discord`/`bridge-signal`; deps serenity/async-trait/serde_yml; daemon bridge startup and `BridgeManager` from `AppState`; `bridge.*` YAML keys (migration above); `bridges` CLI verb; `GET /api/bridge-status`; `POST /api/bridges/toggle`; dashboard bridge config panel (Plugins tab replaces: list, enable/disable, HTML-escaped logs, `set_status` lines).

Contracts kept: R3 behavior-unchanged (acceptance = the v1 command matrix in the PRD bridge section); plugins get NO system ops (no restart/flush/upgrade methods); event schema additive; v1 config boots via migration; Credentials ownership staging (store here, page L3, binding L6).

Build order: credentials store + migration → plugin core (manifest/supervisor/UDS/RPC) → CLI → bridge plugin crate (move + RPC client) → core removals → Plugins tab → docs.

Acceptance (Ray): (1) RPC contract over a real UDS against a live daemon — `initialize` good/bad token, peer-uid reject, grants returned, method-grant matrix (cross-plugin config/kv isolation; ungranted `secrets.get` refused), size cap, in-flight cap, −32601; (2) supervisor — crash loop → backoff → terminal `failed`; connect-auth failures do not consume restarts; clean stop; daemon unaffected; (3) credentials — 0600, masked everywhere, live v1-YAML discord-token migration + `--dry-run`, resolve round-trip, R3's "value absent from plugin config files"; (4) bridge plugin — v1 Discord/Signal command matrix green against stubbed transport + mock LLM, v1 persistence files read, Signal listing equals v1 llama-swap keys; (5) `cargo tree` core shows no serenity.
