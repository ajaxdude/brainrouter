# Leg L6 in full — Cloud providers, Manifest absorbed, LAN federation

Goal (R7): cloud is brainrouter's own decision — providers registered directly, keys from the store, the decision model choosing the cloud model. Federation-lite: any OpenAI-compatible endpoint on the LAN, including a peer brainrouter, is a provider. Distributed-role flows land here.

## Providers (`providers.json`, state dir, 0600 atomic — fleet.json machinery)

- Record: `{id, kind: openai-compatible | anthropic | manifest, base_url, credential_id? (absent = auth-less local gateway), models: [{id, alias?, ctx, tools, price?}], lan_peer: bool, enabled}`. CLI `provider add|list|remove|test <id>` (mutations via daemon, L3 single-writer pattern); dashboard Providers section on the Credentials page: bind credential→provider, Test = cheap completion probe, live per-provider breaker state (new additive `HealthTracker::state()` read API).
- **Selector resolution (the rebind, completing the L7-range contract):** `cloud` (bare) ⇒ the manifest-kind provider with `model:"auto"` when one exists (v1 parity), else the auto pool's top cloud candidate. `cloud/<id>`: (a) unique match on any enabled provider's `models[].id`/`alias` ⇒ that provider + exact id; (b) NO match AND exactly one enabled `manifest`-kind provider with `auto: true` ⇒ **verbatim passthrough to that provider (v1 "accepted without discovery" parity — the migrated owner reviewer keeps routing)**; (c) multi-match across providers ⇒ explicit 4xx naming the providers, no silent pick; (d) `cloud/<provider>/<model>` (provider-qualified) resolves deterministically — the federation form (a peer model `deepseek` exposed by provider `fedora1` is `cloud/fedora1/deepseek`); no `peer/` grammar exists. `validate_model_id` accepts the 3-part qualified form; dispatch precedence: qualified → 2-part → bare, checked BEFORE the named-model catch-all.
- Outbound: `provider/openai.rs` generalized from manifest-only to any OpenAI-compat base_url (Bearer from credential resolution); NEW Anthropic outbound adapter (wire translation, streaming incl. tool/thinking blocks, error mapping; auth = `x-api-key` + `anthropic-version` headers, NOT Bearer; inbound `anthropic.rs` is the reverse-direction reference). Per-provider circuit breakers via `health.rs` (provider-name keyed — migrated manifest provider keeps key `manifest` = today's literal, preserving live breaker state semantics).
- Cloud auto pool: decision `route=cloud` ⇒ enabled providers' models (non-lan_peer by default; lan_peer models pool with locals per role policy), filtered by ctx/tools; ranked by tier fit using a new per-model `tier: fast|balanced|deep` field (operator-entered; peer providers inherit tier from peer-info) with deterministic tie-break = provider record order, then model list order.
- Cost: per-model `price?` ($/1K in,out, operator-entered) feeds the budget guard below and dashboard cost display. Decision-log note: v1's gateway-side cost-aware selection is DROPPED with Manifest; price is the additive replacement surface.

## v1 cloud-parity migration (the reference deployment)

- **Migration table (exact v1 keys — there is NO `manifest.model` key):** `manifest.enabled` + `manifest.base_url` + `manifest.api_key_env` ⇒ provider `{id: "manifest", kind: manifest, base_url, credential: env:<api_key_env> if set, auto: true, models: []}`. `model: "auto"` is the v1 router's hardcoded wire value — recorded as the manifest kind's behavior, not a migrated value. `manifest.*` YAML removed post-migration (snapshot, `--dry-run`, restore `v2.0-p6`).
- **Managed cloud hop shape = v1 exactly:** `cloud`/`cloud/<id>` card routes try the cloud target, then on failure the single `fallback_model` (stage `CloudFallback`, one FailedAttempt event, stop on second failure). Chain widening (multi-candidate) applies ONLY to the auto pool — managed shapes never widen (byte-identical failure corpora).
- **Parity corpus (realized, deterministic, CI-runnable):** recorded triples (request, mock-gateway SSE script, expected: normalized outbound request + event sequence + terminal outcome + breaker transitions) captured by running the `v1-classic` binary against MOCK gateways (not live LLMs — outputs are excluded from comparison). Cases: `model:"auto"` send; `cloud/<id>` passthrough with an EMPTY migrated models list (the B1 case); stream-peek actual-model (64 KiB/TTFT window, byte-preserving reassembly); pseudo-success sentinel (`model=="manifest"` first frame ⇒ fallback WITHOUT breaker failure report; empty stream ⇒ failure); breaker key `manifest` + 429-is-fault trip; cloud→`fallback_model`→stop; reviewer strict (no local hop, escalation on failure).

## LAN federation (Q3: bearer — accepted risks named: plaintext HTTP on trusted LAN + peer-info model enumeration to any token holder; owner's reserved LAN-enable nod carries both)

- **Topology: a SECOND listener.** `lan: {enabled: false, bind, token_credential, expose: [model-keys], rate: {burst, per_sec}}`. The primary `--tcp_addr` (loopback) is NEVER affected — all v1 surface, CSRF gates, dashboard, CLI stay on it. When enabled, a second listener binds `lan.bind`; its route table contains ONLY `/v1/chat/completions`, `/v1/messages`, `/v1/models` (filtered), `/api/peer-info` — admin/dashboard/roles/credentials endpoints are not registered on it at all (listener-level, not middleware-level; test asserts 404 for admin paths on the LAN socket).
- Auth: `Authorization: Bearer <token>` vs resolved `token_credential`, constant-time; 401 otherwise; CSRF does not apply (no browser flows on the LAN listener). **Abuse controls: per-token token-bucket rate limit (`lan.rate`, defaults 20 burst / 5 s)** + **budget guard: providers with `monthly_budget_usd` accumulate est. cost from price×usage tokens; at limit ⇒ provider marked over-budget: cloud routes get 402-class explicit error + dashboard badge + event; warn-only mode available.** Expose filter enforced TWICE: raw requested string ∈ expose, AND the RESOLVED model (no alias/qualified escape into unexposed cloud spend).
- `peer-info`: `{host_id, version, models: [{key, ctx, tools, tier, state}], serving: [...]}` — the provider-editor discovery feed (add peer → pick exposed models with tier prefilled).
- Outbound federation: peer brainrouter = provider `{kind: openai-compatible, base_url http://host:9099/v1, lan_peer: true, credential: <peer lan token>}`. `lan_peer` providers count in `cloud_available` as **peers, not cloud**: review admission `configured_backend` for a `cloud/<peer>/...` card = `peer` (new admission class, strictness = peer-local parity, escalation on failure); `cloud_available` = ≥1 enabled non-lan_peer provider (manifest included), replacing `manifest_enabled` at every admission consumer (builder grep-gate: zero `manifest_enabled` after L6).
- Events: additive `hop: {host, endpoint}` on provider routes with non-loopback base_url; Sankey ROUTING shows hops; cards grouping unchanged (conversation fingerprints come from request content, not origin).

## Removals

`route_cloud` manifest special-casing (providers replace it); `manifest.*` YAML + `config.manifest` struct (migrated); `AdmissionInputs.manifest_enabled` (→ `cloud_available` + peer class); manifest-only breaker naming (generic keys, `manifest` preserved as a key). The Manifest binary on fedora hosts is untouched — brainrouter just no longer requires it. Retirement (R8): manifest kind deleted with owner sign-off once native providers serve the cloud roles.

## Contracts kept

Selector vocabulary + the new qualified form (`auto/local/cloud/cloud/<id>/cloud/<provider>/<id>/subs/bare-id` — Map amended); pinned/auto strictness (L3) unchanged; credentials store unchanged; events additive; v1 configs boot (migration, snapshot, restore `v2.0-p6`); LAN default-off = v1 attack surface byte-for-byte (listener not created).
