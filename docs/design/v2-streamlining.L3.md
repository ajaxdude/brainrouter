# Leg L3 in full — One entry + role cards + decision slot + Credentials page

Goal (R4): a harness is configured ONCE to brainrouter; the app owns the model decision. Four subsystems land together: harness one-entry, role cards, the decision-model slot, the Credentials page.

## Role resolution

- Store: `role_cards.json` (0600, atomic — `src/project_pins.rs` machinery) replaces `routing_profile` + `project_pins` via migration (snapshot; `--dry-run`; restore `v2.0-p3`). Records: `assignments`: `{scope: global|<canonical-git-root>, role: main|review|subagent, assignment: <selector string>}` where selector ∈ `auto | local | cloud | cloud/<id> | <bare-key>` — the SAME vocabulary the Selector-vocabulary contract preserves through L7, validated by the relocated selector validator (`src/routing_profile.rs` shared types move to `src/roles.rs` with `validate_model_id`/`validate_iterations`). Plus `policy`: `{scope → {privacy: cloud-ok|local-only, quality: fast|balanced|maximum}}`. Lookup: project assignment → global → default (`main: auto`, `review: auto`, `subagent: auto`).
- v1 → card migration table (exact, no inference): `Auto→auto`; `Local{Some(id)}→<bare-key>`; `Local{None}→local`; `Cloud{None}→cloud`; `Cloud{Some(id)}→cloud/<id>`. Per-project `main`/`reviewer` pins map identically (full ModelChoice preserved — the owner's cloud-pinned reviewer lands on a `cloud/<id>` card, NOT re-pinned local, NOT auto); `subagent` pin / `subagent_model` → subagent assignment; presets expand through the same table (`RoutingPreset::as_profile` at migration time). A v1 YAML with no `routing:` block migrates main to `local` (v1 default, `src/config.rs:502-504`), NOT auto — the migration must not shift routing behavior at the boundary.
- Role signal: `x-brainrouter-role: main|subagent|review` (default `main`); an explicit `subs`/`brainrouter/subs` selector NAMES the role and overrides the header. Resolution per request: explicit selector (`local`/`cloud`/`cloud/<id>`/bare/`subs`) → v1 path, role = header (events label it), cards bypassed, NEVER policy-clamped (explicit = owner intent; the privacy policy governs machine decisions, not the owner's explicit picks). Else role's card assignment compiles through the same selector path: `auto` → decision slot; any other selector string → direct v1-equivalent route.
- Pinned-card strictness: a pinned card (bare/cloud-id/local) routes with v1 explicit-pick semantics — NO chain fallback, error surfaces (review keeps escalation-to-human on failure; subagent keeps surface-the-error; the strictness tests keep passing). Chain fallback is ONLY the auto path's candidate pool.
- Reviewer source-of-truth: the `review` card is the ONLY reviewer-model config. `review.forced_mode`/`forced_model` YAML + `/api/review-config` + CLI `review-config` migrate into it (mapping via the table above; config keys removed with snapshot). Session snapshot semantics unchanged (a session's card assignment snapshots at session start). Admission gates by the card's backend (`configured_backend` derived from the selector string).
- Review loop calls the router internally with role `review` (no wire header for the review LLM connection itself; the role selects the review card).

## Decision-model slot

- `src/decision.rs`: `trait DecisionModel { kind(); available(); async classify(RequestFeatures) -> Result<Decision, DecisionError>; }`; `RequestFeatures = {role, selector, privacy, quality, project, msg_count, approx_prompt_tokens, has_tools, code_density, last_user_excerpt}` (excerpt ONLY for model kinds — never webhook/plugin); `Decision = {route: local|cloud, tier: fast|balanced|deep, confidence: 0..=1, rationale}`. Tier vocabulary is canonical: quality chips map `maximum→deep`, `fast→fast`, `balanced→balanced`; the v1 classifier words map `local→fast, deep→deep` for the bonsai profile; nudge-budget injection stays where it is (route_auto local arm) and applies to slot-routed locals identically.
- `approx_prompt_tokens` = `body bytes / 4` computed on the raw request at route time (precedent: `src/benchmark_lab.rs`; O(body), no tokenizer). L4 replaces with measured slot data.
- Kinds (`decision_model.kind`): `heuristic` (default, always available); `openai-compatible` (`{base_url, model, prompt_profile, timeout_ms}`; **Bonsai migrates to exactly this** with `prompt_profile: bonsai` — today's prompt + one-word-response grammar (`local`/`deep`/other, `src/classifier.rs` parse_decision) preserved verbatim); `structured-schema` (same transport; typed question schema + strict JSON decision; the Clef contract); `webhook` (`{url}` POST — features JSON, NO excerpt; decision JSON back); `plugin` (`{plugin_id}`) — server-initiated `decision.classify` REQUEST over the plugin connection: a PROTOCOL addition (not a grant line): request-id correlation + timeout (`decision_model.timeout_ms`), gated by `min_daemon_version` protocol bump (additive surface, version-negotiated at `initialize`).
- Failure-path matrix (per kind, binding): `prompt_profile: bonsai` (the migrated config) preserves v1 safe defaults EXACTLY — HTTP error, timeout, unparseable reply, empty last message ⇒ `route=cloud` with `fallback: v1-safe`; low-confidence (<`min_confidence`, default 0.4) ⇒ heuristic + `fallback: heuristic`; slot unavailable (server down) ⇒ heuristic + `fallback: unavailable`. Fresh-config kinds (structured-schema/webhook/plugin) fall to heuristic on any failure. Continuity acceptance runs on a GOLDEN CORPUS: recorded v1 (prompt, raw classifier word, v1 decision) triples captured from the v1-classic binary, replayed against the migrated profile — deterministic; the failure corpus is a named table, not live flapping.
- Guardrail clamps (apply to slot decisions, NOT explicit selectors): privacy `local-only` ⇒ `route=local`; quality floor raises tier (never lowers); pool-by-ctx only when the model's ctx is KNOWN (llama-swap config `parameters.ctx` via the config brainrouter already reads; unknown = pool with ctx=unknown ranked last for big requests, clamp not applied, logged) — L4's catalog replaces this source.
- Auto-path selection: candidate pool = llama-swap models (config keys + `/v1/models`) + server-mode identities; filter by route + known-ctx; rank by tier fit (catalog metadata: quant/family size class where known); chain = next candidate on CONNECT/response-headline failure only (never mid-stream after first byte); `fallback_model` config remains as compatibility seed, logged deprecated.
- Config: `decision_model: {enabled, kind, base_url?, model?, prompt_profile?, timeout_ms?, plugin_id?, min_confidence}`; `bonsai.*` migrates (server lifecycle management `bonsai_server.rs` stays as the launch backend for the migrated preset). Invariant: prompt-rewrite ⇒ `decision_model.enabled` (any kind; heuristic satisfies), enforced at the same handler.
