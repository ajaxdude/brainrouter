# Leg L5 in full — strixite + hipfire adapters

Goal (R6): the icon fleets die. strixite (gfx1151) and hipfire (gfx1100) become supervisor-managed engines — same flow on every machine. L4 rails carry the weight; L5 adds the two adapters, the cutover mechanics, Active-Consumer protection, and pilots.

## Active-Consumer protection (replaces "self-provider pin" prose; the L4 scheduler's pin/drain input)

- **Active-Consumer Set (ACS)** for an endpoint = EVERY live routed stream to it: proxy in-flight rows (registration at route time, L4's authorized additive change), in-process router calls (review loop `route_with_choice` — the router's stream wrapper increments/decrements an endpoint-keyed counter; today this traffic creates no rows), and L6 LAN-peer streams (they ride the proxy, covered). The Bonsai/decision model is an external llama-server — L4 sized-pin, not ACS.
- **Protection span:** a model is protected while its endpoint is in the ACS **plus a configurable idle grace (`self_provider_grace_s`, default 120 s)** after the last stream ends — bridging tool-execution gaps so a live session is never mid-swap; span tracked per endpoint in the scheduler.
- **Cutover re-check:** at the SIGTERM point, the scheduler re-reads the ACS; a stream arriving since admission ⇒ the cutover RE-QUEUES (bounded single re-check, then Failed with reason).
- **Override is ONE action:** `swap ensure <model> --override` (CLI) / the dashboard "Swap anyway" button — bypasses protection span for that operation, audit-logged (who, when, target). `pin rm` remains only for L4's persistent sized-pins. Block reason: `blocked:active-consumer` (honest name: any protected consumer, including LAN peers, blocks eviction — correct behavior, per the Map's drain-first contract).

## strixite adapter

- Registry: strixw model dirs `~/models/<name>/` (weights.strixw, vision.strixw, ngram table, tokenizer/config/generation_config/preprocessor_config, sha256.txt; v0.4.0 vision-required; file validation at spec build = Failed pre-spawn). Conf registry: named profiles (base/swift × 256k-desktop/512k-headless) as TEMPLATES carrying `min_mem_gib` (seeded: 256k→90, 512k→115; owner-maintained data, GiB; compared against `/proc/meminfo` MemAvailable KiB).
- Ports: launching `strix_server --config <conf> --weights <weights>` takes the port FROM THE CONF — so per-model ports = per-model GENERATED confs (profile template + supervisor-allocated port, `--print-config` validated at spec build). Allocation range is registry-managed and avoids ALL Residency-view endpoints (post-observer: shim/native/container/external, including imported llama-swap entries with explicit `--port`).
- **Residency observer (external engines):** read-only `pgrep` discovery of `strix_server`/`hipfire` processes = external residents (source=external + engine field), endpoints probed via `/v1/models`. Icon-launched servers are therefore VISIBLE: attach-not-spawn (Ready-at-external), counted in budget, and **cutover SIGTERM targets ONLY supervisor-spawned/adoption-marked pids — never an external resident** (start-ownership, L4 binding). Swapping onto a device whose external server is live requires that server to drain (its proxy streams are in the ACS) + an explicit operator action: `swap adopt` (register the external pid as a native resident with marker) or stop it (icon retirement); dashboard offers both with the squat warning. The migration window — icons and supervisor coexisting — is exactly where the fedora1 squat incident lived; it is structurally closed by observer + pid-scoped kill.
- Cutover state machine (binding): SIGTERM (own pids only) → poll that pid gone → sleep 2 (clock injectable) → `MemAvailable ≥ profile.min_mem_gib` → spawn (systemd scope, L4) → poll `/v1/models` expected stem (~30 s) → Ready. Gate-blocked ensure = state `Waiting(gate)` visible in the queue with the threshold and current value; 10-min timeout ⇒ Failed with reason + `--force-gate` (audit). Hung-start: failed spawn holding GTT ⇒ SIGTERM ⇒ kill -9 after grace ⇒ re-run gate. Serialized per-device swap lock. One resident per device (`exclusive: true`): ensure of a second strixite model = evict-then-spawn swap, never co-resident.
- Load progress: readiness poll only ⇒ indeterminate + EWMA ETA (L4 native path).

## hipfire adapter

- Registry: card files `~/.hipfire/models/` (`*.mq4` + `.mtp` sidecar auto-loaded by stem; sidecar presence recorded in spec; missing sidecar = warn, engine auto-loads by stem — validation at spec build). Launch = `hipfire serve`, engine-validated flag schema keyed on the engine version marker (probe discovers install root + version): re-derived on version change, schema drift = Engines-tab badge (an engine upgrade can't silently poison the stored schema; no `--mtp` speculative flag — schema rejects it by construction).
- Port ownership: single-owner rule on `:8080`. Boot probe detects `hipfire-serve.service` (system) ⇒ Residency shows it external; the migration (Q4 default) = disable the system unit + register a brainrouter-managed user-scope unit — the post-migration resident is NATIVE (supervisor-spawned, adoption-marked, survives daemon restarts via its own unit scope); external-pinned applies only to the not-yet-migrated system unit. Squat detection: expected-stem mismatch at the endpoint ⇒ Failed + banner (structurally impossible to lose a suite to a squatted port again).
- Context math pre-forward: measured = max(usage-backfill history, body estimator); `max_tokens` default = engine remaining context (max-seq − measured prompt) when absent; 400 surfaced with the shortfall.
- Cutover: stop = SIGTERM + port-free gate (`/health` must FAIL before next spawn); start → `/v1/models` stem poll. Same exclusive class (one resident per device).

## Fleet wiring + retirement

- Per-host profiles: strix-halo = strixite + gufo + llama_swap_shim + sized pins (decision model, self-provider); fedora1 = hipfire (+ llama_cpp); fedora2 = strixite prod + deepinfra (L6). Engines tab offers from platform probe (strixite/gufo only on gfx1151; hipfire on gfx9/10/11).
- Icon retirement is an OPERATOR-GATED pilot step per machine (charter: fedora1/fedora2 destructive actions = reserved nod, obtained per machine in the digest): stop icons once, register models, set pins; UPGRADE.md carries per-host steps. The icon UX people love (window opens before load) = L4 queue UX: request queues at "loading", first token when Ready.

## Contracts kept

L4 rails unchanged (adapters = trait impls + data); shim/gufo/ds4/llama_cpp byte-identical; Residency source enum + engine field (external residents land with the observer); ACS consumes L4's authorized inflight additive registration + a router-internal counter (new, in-process only, no schema); icon-era invariants (stem assertion, port-free, MemAvailable gate, pid-scoped start-ownership, engine-validated flags) are adapter code.
